# Accepted live-pad capture — private 2.0 connection

`BB_WITH_LIVE_CAPTURE=1` adds an explicitly armed audio-owner ring of32 manual input events. It does not turn on a recording UI. Legacy profiles default OFF; the private composition recipe enables it and retains all four APIs for actual native cost measurement.

An event is appended only after an accepted `BB_CMD_DRUM_TRIGGER` has sounded through the existing owner. Sequencer/delayed events and other-layer auditions are excluded. The frame is the actual consumer frame, the source voice is resolved from the native alternate mode or sampled note map, and raw velocity, target, kit and source epoch are retained. Unknown mappings invalidate the pass. The source identity is the applied ticket plus family epoch/kit/transport epoch; timing changes invalidate it even if the tempo is restored in the same command drain.

Begin/read/end/discard run on the main loop through the existing short IRQ-save guard; the audio consumer produces events. No extra thread, DSP route, flash, transport or pattern write. Begin requires idle queued input and a running rich source under the currently qualified native808/sampled owner. Straight timing is required for this initial connection; swing-aware musical quantization remains unfinished. Current mappings explicitly exclude909 and owner-bridge profiles until qualified.

Read one event at a time and treat it as provisional. The32-slot ring wraps as the main loop drains it. Overflow latches an explicit whole-pass refusal, retains the existing events and never overwrites the oldest item. End returns BUSY while queued input remains; it must not silently exclude an earlier queued pad. STOP closes capture and permits existing events to drain. Only successful end and a complete drain to CLOSED, without any source/timing/fault/overflow error, may precede take publication. Explicit discard is required before another pass.

The actual-C integration fixture exercises engine hit→captured frame/raw velocity→existing quantized recorder→stopped arranger working-part commit→Undo/Redo. It now anchors the recorder to the atomically captured source step and fractional phase, with exact rational step duration for the source lattice. The single-hit fixture is not a complete count-in, long-pass timing or physical acceptance test. It preserves the complete original phrase and appends one hit through one journal action. Capture never mutates the active phrase itself. The current phrase format still reduces authored hits to grid/accent classes: full expressive velocity/microtiming representation remains unfinished even though this input ring retains raw velocity.

Still required: REC/overdub UI, phase-aware count-in/metronome and grid policy, complete KEEP/Cancel and refused-take feedback, project/scene save, expanded-engine validation, actual target timing/stack and hardware/listening/recovery acceptance. The native build is a fit/cost check only. No public1.5 change or device install follows from these tests.

## Arrangement ownership and direct loading

A playing arrangement may reserve both rich-phrase inboxes for its queued complete section. A direct per-layer phrase request then returns refusal without changing audio, the queued section, the model, sources or the caller's output ticket. Valid payload and engine capability do not grant ownership of reserved storage. Use the arranger's whole-section cue path for live arrangement changes. For a stopped authoring commit, request controller STOP, poll the actual acknowledgement/release, and require can_edit before publishing. Never clear inboxes or synthesize a successful request to bypass this boundary.

After acknowledged STOP and controller polling, the reserved inboxes become free and the same unchanged phrase can load through the ordinary direct API. With rich rendering enabled its status is APPLIED even while transport stays stopped: loaded musical state does not mean audible playback. The regression verifies this exact lifecycle and byte-preserving refusal. This is private2.0 arrangement behavior; it is not an explanation or hardware verdict for earlier public1.5 ALGO browsing feedback.

## Rational source-grid anchor

The capture clock also snapshots rich-source phase, current source step, lattice and length under the same owner guard. `bb_live_record_begin_phase` accepts an origin frame, numerator/divisor in frames per source step, initial source phase and source cell. For the engine's straight clock these are sample_rate×6000, BPM×(200/400/600), the captured rich phase and source step. The integer-duration legacy entry remains a wrapper with divisor1/phase0/cell0.

Nearest-grid calculations split the64-bit elapsed frame count before multiplication. A bounded residual product retains fractional-sample phase without floating point, whole-step rounding or overflow at UINT64_MAX. Exact half steps round forward and source-cell wrap is preserved. This is main-loop quantization, not extra work in the audio interrupt.20,000 randomized full-width cases compare to an independent128-bit host reference, with explicit invalid/early/tie and120BPM half-sample cases. The native recipe now roots the complete recorder/working-part commit APIs for honest combined cost. UI/count-in policy and full expressive storage remain open.

## Private control prototype (qualification in progress)

From ARRANGE, add/select a source section and tap REC while stopped. K1 selects A/B; K2 chooses NOW or NEXT BAR; K3 selects accent; K4 explicitly enables/disables that layer. Tap REC to start an indefinite temporary performance of the selected A/B/Dillo sources, without rewriting arrangement repeats/duration or sounds/mix. The layer must be enabled/unmuted and timing straight. A next-bar rhythm/visual count-in precedes capture; it is not yet an independent click metronome.

White keys1–11 audition/overdub the physical drum lanes. The Dillo trigger view animates accepted hits during count-in/recording; early count-in hits sound but are not committed to the take. REC, PLAY or HOME requests supported STOP and waits for acknowledged idle ownership, then shows the closed RAM take. EDIT keeps one immutable working part/journal action; REC discards. HOME during review cannot silently discard it. Undo/Redo after KEEP restores the old/new source references. SAVE during recording explains that the take must be kept and project-file saving is still unfinished.

A full Undo journal requires named EDIT confirmation before clearing history and keeping the take. REC cancels that confirmation while retaining take and history; a separate subsequent REC discards the take. Source/work-capacity preflight precedes the confirmed history clear, with the same main-owned model/revision/capability snapshot reused for commit. A full working-part store refuses KEEP while retaining the take and original model. Source/timing/mute/enable changes or input/capture overflow refuse incomplete takes; pending STOP or missing source acknowledgement has a bounded timeout.

This prototype still needs frozen-source complete native/browser qualification and publication into the local preview. Full expression, retrospective capture, audible metronome, project/scene-file persistence, native stack/timing/listening/recovery and release acceptance remain unfinished. The private recording workspace is now explicitly reserved in pool RAM; no scene/flash is written by these controls.

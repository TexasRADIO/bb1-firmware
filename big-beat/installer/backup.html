Backups and shared flash storage

Back up in the firmware you are leaving, before switching. A successful firmware update does not guarantee that another firmware can read or preserve its music. Keep the original firmware package, matching sample bank and any project/scene exports together.

  1. In the BB1 2.1 browser player, export each project you need using its project-file workflow. This does not export all music already saved on a physical FM-1. Keep separate versions of unsaved edits. Check that the file can be opened in the corresponding browser player. A downloaded project does not back up every saved scene, global setting, USER kit or sound bank.
  2. Record or export every saved scene, USER-kit choice and global setting you need using that version's supported tools. The installer's optional legacy archive attempt is not a verified full BB1 2.1 backup; an unavailable archive must not be treated as a successful backup.
  3. For another firmware, use that firmware's own backup/export tool and retain its restore instructions. Stock V15 does not provide the legacy archive used here. If there is no supported export, copy down settings/patterns and record audio before proceeding.
  4. Keep BB1's matching firmware and sound library: 2.1 needs library 2.1; public 2.0 needs library 1.4; corrected-ID 1.5 returns with its original 1.2 library. Older BB1 may refuse newer scenes. Official stock firmware cannot open BB1 projects.

SLOOP has been removed in BB1 2.1. Older projects that depend on SLOOP are unsupported; no migration is provided. Current project, scene and USER-kit features remain.

Each save copy occupies one 4096-byte sector. The payload is written before the commit header, followed by readback validation. Host fault tests exercise this storage layer; they do not establish physical power-cut or reboot acceptance.

The installer also writes the required sound library at 0xA0000–0xDC000 (245,760 bytes). Firmware updating uses its own application and OTA staging areas; those are not scene backups. Region B is not written by the 2.1 sound-library step.

Known cross-firmware overlap

RemoteFM1 0.3.1's release notes declare writes at 0x97000–0xD8FFF inclusive. This intersects all four BB1 scene pairs and part of BB1's library area (0xA0000–0xD9000, exclusive end). Its author separately warns about ChoralRoot/FIZZ saves. This is a comparison of declared ranges, not a tested transition or a complete map of those firmwares. Do not assume USER/global settings are preserved merely because they lie outside that declared range.

Versioned references: frozen BB1 firmware/src/storage.c, bb_target_session.c, and the 2.1 asset writer. The installer refuses an unsupported starting runtime ID before issuing its update command; this does not prove preservation or recovery.
